jflat — multi-format structure flattener / unflattener

Usage: jflat [options]

Reads structured data from stdin (TOML, YAML, JSON, CSV, or TSV) and
outputs a flat tab-separated table: one leaf value per line.

Format (flatten):
  <path> TAB <type> TAB <value>

  path    jq-style: "." for a root scalar, ".key", "[0]", ".key[0].sub"
          Keys containing . [ ] " \ newline or the separator are quoted: ."key"
  type    null | boolean | number | string | time | object | array
          object and array only appear for empty containers ({} / [])
  value   JSON representation of the value; time uses RFC3339

Format (unflatten, -u):
  Reads the flat table and reconstructs structured output.
  time type becomes a native TOML datetime in TOML output, plain string elsewhere.

  env format:
    Outputs KEY=value lines suitable for shell sourcing.
    Path segments are uppercased; non-alphanumeric chars collapsed to a single '_';
    leading/trailing '_' stripped. Array indices become bare numbers (e.g. HOSTS_0).
    String values are single-quoted with embedded ' escaped as '\''.
    null becomes an empty value (KEY=). Empty object/array entries are skipped.
    Key collisions (e.g. .foo.bar and .foo_bar both → FOO_BAR) produce duplicate lines.

  csv / tsv format:
    Rows become array elements. By default the first row supplies column
    names on flatten, and objects are written keyed by those names on
    unflatten (-u csv/-u tsv also emits a header row in that case). With
    -noheader, columns become object keys "0", "1", ... (positional)
    instead.
    csv defaults to sep=',' with RFC 4180-style quoting allowed; tsv
    defaults to sep='\t' with quoting disabled. Override with -svsep,
    -svquote/-svnoquote. On unflatten, a field that needs quoting (contains
    the separator, a quote, or a newline) is an error if quoting is
    disabled, and nested object/array cells are always an error.
    On unflatten, a top-level object is treated as a single row; a
    top-level scalar (null/boolean/number/string) is written as a single
    cell (header output is an error in that case, since there is no row to
    name -- pass -noheader for scalar/no-name output).

Options:
  -h, --help      show this help
  -v              show version
  -f <fmt>        force input format: json, yaml, toml, csv, tsv  (cannot use with -u)
  -nosort         keep original key order instead of sorting paths
  -sep <str>      separator between fields (default: TAB)
  -u <fmt>        unflatten mode: output as json, yaml, toml, env, csv, or tsv
  -noheader       treat rows positionally, no header row
                  (default: first/emitted row is column names)
  -svsep <char>   separator character for csv/tsv (default: ',' / '\t')
  -svquote        allow RFC 4180-style quoting for csv/tsv
  -svnoquote      disallow quoting for csv/tsv (fields with the separator
                  are an error on unflatten)

Auto-detection order (when -f is not given): TOML first, then YAML/JSON.
JSON is a subset of YAML and will be parsed by the YAML parser.
CSV/TSV are never auto-detected; pass -f csv or -f tsv explicitly.

Examples:
  # flatten a TOML config
  cat config.toml | jflat

  # flatten and filter errors
  cat data.json | jflat | grep '"error"'

  # round-trip
  cat config.toml | jflat | jflat -u toml

  # force YAML parser, no sort
  cat doc.yaml | jflat -f yaml -nosort

  # unflatten to JSON
  cat flat.tsv | jflat -u json

  # export config as env vars
  cat config.json | jflat | jflat -u env
  cat config.json | jflat | jflat -u env | source /dev/stdin

  # flatten a headered CSV, custom semicolon separator
  cat data.csv | jflat -f csv -svsep ';'

  # convert CSV to JSON
  cat data.csv | jflat -f csv | jflat -u json

  # convert JSON array of objects to TSV
  cat data.json | jflat | jflat -u tsv
